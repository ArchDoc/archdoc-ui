An architecture control plane for AI-assisted development

ArchDoc is an interactive software modeling platform that empowers engineers to understand the systems AI is modifying and stay in control of the driver seat. Open-source, AI-first, analyze current state, propose future state changes, map architectural concepts to code, and help developers of any experience level explore and learn the system they're building.

Why
  • AI agents change code faster than people can follow the architecture.
  • Architecture docs drift from code and stop being trusted.
  • Generated repo wikis describe code but aren't owned by anyone.
What
  • A human-owned model in each repo: who uses the system, what it's made of, how people use it, and what happens to the data.
  • Linked to code, checked in CI, queried by agents.
  • Federated across repos into one enterprise view.
How
  • A fresh TypeScript monorepo, built in 9 phases.
  • ArchDoc models itself from Phase 1 on.
  • A thin first slice proves the loop before the rest is built.
What we're building

One model, one engine, four ways in

The model lives in .archdoc/ next to the code. A deterministic engine answers every question. People and agents reach it through the surface that fits their moment. The engine contains no LLM: your own agent does the reasoning.

Guardrails

How we'll work, and what could go wrong

Working principles

Dogfood from Phase 1.ArchDoc's own repo is the first and hardest test of every feature.
Exit tests, not dates.A phase is done when its exit test passes on a real repo.
People approve, agents suggest.Every fact carries its origin. AI suggestions only become real through a reviewed diff.
Design for later, build for now.Namespaces and data references are in the schema from day one, so federation and the data layer are additive.
Interoperate, don't compete on syntax.Import LikeC4 and Structurizr. Win on code mapping, change review, and learning.

Risks and mitigations

The model drifts from the codeDrift checks in CI are a core feature, and code mappings make staleness visible.
AI invents architectureAnalyzers before inference. Suggested facts render dashed until accepted.
Journeys and data rules go stalecheck validates every step, mapping, and state transition. Schemas are imported, not retyped.
Version skew across reposPinned imports in archdoc.lock, plus dangling-reference checks.
Scope creep for a small teamPhase gates, plugin APIs for languages, and agents doing much of the build.
